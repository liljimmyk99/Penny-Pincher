# AGENTS.md — /web

Read the root `AGENTS.md` first. This file adds rules specific to the React web app.

## Stack

- React (TypeScript recommended)
- **Build tool: Vite. Test runner: Vitest with Testing Library** (React Testing Library and `jest-dom` matchers). Component and screen tests run in Vitest's jsdom environment.
- Talks only to the backend API described in `/api`. Generate the API client/types from the OpenAPI spec rather than hand-writing them.
  - Types are generated by `openapi-typescript` into `src/api/schema.gen.ts` (never edit it). After changing the spec, run `npm run gen:api` and commit the result; `npm run check:api` fails if it is stale.
  - Calls go through the `openapi-fetch` client in `src/api` (`useApi()`), wrapped in `unwrap()` inside TanStack Query `queryFn`/`mutationFn`. Use `Schemas["Category"]` etc. for types.
  - The client adds the session token as a bearer header and reports `unauthenticated` / `session_expired` (401) to one `onSessionError` handler (the app clears the session and shows the sign-in screen). There is no refresh and no retry. A `403 password_change_required` sends the user to the Change password screen. `admin_required` is left to the caller. `auth/login` is the only call made without a token.
  - Failures throw `ApiError` (`status`, `code`, `details`). Show `errorMessage(err)` to users and `fieldErrors(err)` next to form fields; branch on `code`, never on `message`.
- Auth is the app's own username and password sign-in (root §10, #182); there is no third-party SDK and no sign-in configuration baked into the build.
  - `src/auth` exposes an `AuthService` interface (`signIn(username, password)`, `signOut()`, `changePassword(current, next)`, the current user and token). The real one calls the API's `auth/*` routes through the generated client; tests use a fake (`src/test/fakeAuth.ts`). Only `src/auth` reads or writes the token.
  - **Token storage:** the session token (never financial data) is kept in `localStorage` under one key so a 30-day session survives restarts. It is cleared on sign-out, on `unauthenticated` / `session_expired`, and when the password is changed elsewhere. The CSP below is what limits what can read it.
  - The session store (`createSession`) is the API client's `onSessionError`. A user flagged `must_change_password` can only reach the Change password screen and Sign out.
  - Never log or put the password, the token or the username in a URL, query string or error report.
- **Routing: React Router** (`react-router`). Routes live in `src/App.tsx` (`AppRoutes`) inside `AppShell` (`src/shell`); the sidebar order is `NAV_ITEMS` in `src/shell/navigation.ts`. Each screen renders a `Page` (`src/pages/Page.tsx`), which sets the tab title and gives the `h1` that takes focus after navigation. Tests render `AppRoutes` in a `MemoryRouter`.
- **UI components: shadcn/ui** (root §10, #165), `new-york` style, Zinc base, on **Tailwind CSS v4** (`@tailwindcss/vite`) and the design tokens below.
  - Components are added with the shadcn CLI into `src/components/ui/` and owned by us. They are built on Radix primitives and `class-variance-authority`; `cn()` (`clsx` + `tailwind-merge`) lives in `src/lib/utils.ts`.
  - **Never edit a generated primitive for a one-off look.** Wrap it in an app component outside `ui/`, or add a variant to its `cva` definition. Edits inside `ui/` are only for app-wide rules (the 44px default size, CSP fixes), with a short comment saying why.
  - **Sizes:** Button, Input and Select are 44px tall by default (shadcn's 36px is not the default). A smaller size only where a dense table needs it and the target stays reachable.
  - Icons: `lucide-react`. Toasts: Sonner. The merchant combobox: cmdk (`Command`) in a `Popover` (#174). The input is ours, outside the `Command` tree, and drives the highlight through `Command`'s controlled `value`: cmdk's `Command.Input` replaces the id, always says `aria-expanded` and takes Enter (it would pick the first suggestion instead of moving to the next row), so `ui/command.tsx` leaves out `CommandInput` (and `CommandDialog` until shadcn's `dialog` is added).
  - The migration finished in #180: every screen is on these components, Tailwind's preflight is on, and the old hand-built CSS (`styles/controls.css`, `styles/global.css`, the `--color-*` aliases) is gone. App-wide element defaults (body, plain links, the focus outline, reduced motion) are in the base layer of `src/index.css`.
  - **Radix only through `ui/`:** ESLint (`no-restricted-imports`) refuses `radix-ui` and `@radix-ui/*` imports outside `src/components/ui/` (and `src/lib/cspSafeStyles.test.tsx`, which tests the primitives). Use or add a wrapper there.
  - **Setup (#166):** `components.json` configures the CLI (`npx shadcn@latest add <name>`); `@/` means `src/` (Vite, Vitest and `tsconfig.json`). After adding a component, check its imports: the CLI has resolved `@/lib/utils` to an npm package named `cn` instead, which must not be installed. `src/index.css` loads Tailwind's theme, preflight and utilities and `tw-animate-css`, imported in `main.tsx` before `styles/tokens.css`. jsdom stubs for Radix (`ResizeObserver`, `scrollIntoView`, pointer capture, `matchMedia`) are in `src/test/setup.ts`.

Rules come from `newPasswordRules` in `src/lib/password.ts`, with `MIN_PASSWORD_LENGTH` and `generatePassword`.

The value lives only in the dialog's state; the once-only sign-in details view copies it with "Copy sign-in details" and a toast ("Sign-in details copied", never the password itself).
  - **Content primitives (#170):** `card`, `badge`, `alert`, `table`, `tabs`, `toggle`, `toggle-group`, `progress`, `skeleton` and `tooltip` in `src/components/ui/`, adapted app-wide (each edit has a comment). Domain colours come from tokens only, never hex.

    - **Import banner** is an `Alert` (`info` running with a `Progress` along its foot, `success` finished, `destructive` stopped) with ghost-button actions and an icon Dismiss.

    - **Frame:** card fill, 16px radius, `--shadow-dialog`, the `--backdrop` overlay, fade and zoom (off with reduced motion). At most 480px wide (widen with `className`, e.g. 560px for the editors, 720px for the income dialog), 16px from every edge at phone width, and it scrolls inside when tall. **Centred with `inset-0` and auto margins, never a transform**, so `position: fixed` popups inside it (the merchant list) still line up with the viewport. Dialogs don't use `Sheet` (that is the mobile sidebar): the centred dialog fits a phone.
    - **Dialog:** `DialogHeader` (title, then description) and `DialogFooter` (buttons end-aligned, wrapping). `DialogContent` has a 44px ghost **Close** button (`aria-label="Close"`) unless `showCloseButton={false}`. Cancel is an `outline` Button inside `DialogClose asChild`; the main action is the `default` Button.
    - **AlertDialog** (destructive confirmations, through `DeleteDialog`): no Close button and no click-outside dismissal. Focus starts on Cancel (`AlertDialogCancel`, `outline`); `AlertDialogAction` is `destructive` and names the outcome; `AlertDialogMedia` is the 44px danger tile for the icon. An action that waits on the server calls `preventDefault()` so the dialog stays open until the caller closes it.
    - **Focus returns to the opener** even without a `DialogTrigger` (our dialogs open from state): the content remembers what had focus when it opened and focuses it again on close, unless another dialog has opened in its place (apply a template → the reset confirmation) or the opener is gone (a menu item).
    - Open state stays where each screen keeps it (props or the URL). While something is saving, `onOpenChange` ignores close requests (Esc, Close, Cancel).
  - **Adding a component:**
    1. `npx shadcn@latest add <name>` from `web/`. It writes `src/components/ui/<name>.tsx` (and any Radix import through the `radix-ui` package).
    2. Check the imports: `@/lib/utils` must stay `@/lib/utils` (the CLI has rewritten it to an npm package named `cn`, which must not be installed), and nothing new should land in `package.json` you didn't expect.
    3. Keep the generated file as shadcn wrote it where possible. Edit it only for an app-wide rule (the 44px default size, a CSP fix, tokens instead of hex), each edit with a short comment saying why.
    4. An app-specific look goes in a wrapper outside `ui/` (as `FormField`, `StatTile`, `DeleteDialog` do) or a new variant in the component's `cva` definition, never a one-off edit of the primitive.
    5. A new Radix primitive or a dependency that injects styles gets a case in `src/lib/cspSafeStyles.test.tsx`; then run `npm run lint && npm run typecheck && npm test`.
- **No charting library**, and shadcn's `chart` component (Recharts) is not used. The approved charts (root §6.11) are hand-built React components, the same way the design canvas draws them:
  - ranked, paired, diverging and sparkline bars are elements sized as a percentage of the largest value (HTML or SVG)
  - the donut is a CSS `conic-gradient` ring (or SVG arcs)
  - one component per chart type (e.g. `RankedBars`, `PairedBars`, `DivergingBars`, `Donut`), shared by every screen
  - every chart has a text alternative (see Interaction patterns)
- Do not add a major dependency without noting it in the root file.

## Rules

- **Money** arrives as integer cents. Convert to display strings in one shared formatting utility; never do arithmetic on floats or on formatted strings.
- **Dates** are `YYYY-MM-DD` calendar dates. Do not let time zones shift them.
- **Online-only in v1:** no offline cache and no storing financial data in localStorage/sessionStorage. Show a clear error when a request fails. (UI preferences such as theme and sidebar state may be stored locally.)
- Keep server state in a data-fetching layer (e.g. TanStack Query or equivalent), not copied into component state.
- Auth goes through the `AuthService` module in `src/auth`; the rest of the app never touches the token or calls `auth/*` itself.
- **Content-Security-Policy** (set by the proxy in `deploy/Caddyfile`; `docs/security.md`): no inline `<script>`, no inline `<style>` elements, no `eval`.
  - Code that must run before first paint goes in a file in `public/` (as `theme-init.js` does).
  - Style with CSS files or React's `style` prop, which the CSP allows.
  - A dependency that injects `<style>` elements has its CSS adopted as a constructed stylesheet instead: an alias to a stand-in (`src/lib/cspStyleSingleton.ts` for Radix's scroll lock) or a rewrite in `plugins/cspSafeStyles.ts` to `src/lib/cspAdoptedStyles.ts` (Sonner, Radix Select and ScrollArea). The audit of the shadcn dependencies is in `docs/security.md` (#168). A new dependency, or a new Radix primitive, gets a case in `src/lib/cspSafeStyles.test.tsx`.
  - Never set a `style` attribute with `setAttribute` or HTML markup; the CSP blocks it.
  - Loading anything from a new origin (scripts, fonts, frames, API calls) means updating the policy in the same change.

## Design system

Every value below is a token in one place, `src/styles/tokens.css`, under shadcn's variable names plus our domain names; `src/index.css` exposes them to Tailwind with `@theme inline`, so `bg-card`, `text-muted-foreground`, `border-input`, `text-income`, `bg-refund-pill` and so on follow the theme. Do not scatter hex values through components or charts (`charts/charts.css` and arbitrary values such as `shadow-[inset_0_0_0_1px_var(--ring)]` read `var(--…)` by the token names).
- Change a colour in the light or dark block. `src/styles/tokens.contrast.test.ts` checks every pair below (text 4.5:1, bars and focus rings 3:1); add a pair there when you add a token.

**Type:** Geist (400–700) from Google Fonts (already allowed by the CSP), system sans-serif fallback. Tabular numerals for every money column.
- Page title 32px/600 · section title 18px/600 · body 14px · labels 13px/500 · tile value 26px/700

**Shape and spacing:** base radius 10px (md 8px for buttons and inputs, xl 14px for cards), cards with a 1px border; controls 44px tall; badges radius 6px; focus ring 3px of primary at 35%. Page padding 32px top, ~40px sides; 24px between sections, 16px between tiles. Touch targets at least 44px.

The domain values are v1's, re-checked against the Zinc neutrals in #167. Changed there: toast, info alert and selected moved to the Zinc and blue-950 shades of the V2 canvas.

**Known exceptions to 3:1 (as in v1):** field borders (`input`, about 1.5:1 in light), because fields are also marked by their label and their card fill on the page colour; and brand orange on white (2.8:1), used only for the logo and the unconfirmed dot, which always sits beside text that says the same. Don't use brand orange for anything that carries meaning on its own.

- Orange, blue and green are the action/accent colors; white is an accent only, never a primary color.
- Text must meet 4.5:1 contrast (3:1 for large text). Colors that must be told apart also differ in lightness, not hue alone.

**Change indicators (month over month, year over year):** colour by meaning, not direction. Orange = worse (spent more), blue = better (spent less). For **Saving the colours flip**: saving more is blue (good), saving less is orange. Always show an ▲/▼ arrow and a +/− sign too, so colour is never the only signal.

**Icons:** `lucide-react` line icons (2px stroke, 24px grid, shown at 18px). No emoji.

**Theme:** Light, Dark and System, chosen in the account menu. Default to System. Dark mode is the `dark` class on `<html>` (shadcn's convention, and what Tailwind's `dark:` reads); `data-theme="light|dark"` is set alongside it; `tokens.css`'s dark block matches either, and the tests read it. `src/theme` and `public/theme-init.js` (before first paint) set both.

## Layout and navigation

- Left sidebar, 232px wide, dark background. Items in this order: Summary, Add entries, Transactions, Yearly, Trends, Templates, Categories & sources, Import. The current page is highlighted (the `sidebar-accent` pill, V2) and marked `aria-current="page"`.
- **Collapsible sidebar:** a chevron button next to the logo collapses it to a ~76px icon-only rail (logo, icons, avatar) and the content widens. Links keep their accessible names when collapsed. Remember the choice per user (a UI preference, safe to store locally).
- **Phone width (below 768px):** a dark top bar with a menu button and the logo; the sidebar opens from it as a sheet (focus trapped, Esc closes) and closes when a page is picked.
- Account button at the bottom of the sidebar opens a menu: name and username (the username once if there is no display name), Appearance (Light / Dark / System), Settings (⌘,), Import transactions, Export data, Admin dashboard (admins only), **Change password**, Sign out. Change password opens the Change password dialog (below).
- Main content is fluid; cards and tables wrap or scroll horizontally inside their card on narrow windows. No horizontal page scroll.

### Refunds (in the transaction list)
- **Refund rows:** negative amount in refund green on a light-green row. Below the merchant: "Refund for <merchant · date · amount>", linking to the original.
- **Tags:** "Full refund", "Partial refund", "From <Month>" when the original is in an earlier month, or "Not linked".
- **Original expenses** show what happened to them: "Refunded in full on <date> · net $0.00", with the amount struck through, or "Partly refunded · −$X on <date> · net $Y".
- **Filter chips:** All, Refunds, Not linked.
- **Linking dialog:** for an unlinked refund, "Link…" opens a dialog that searches recent expenses, shows a **Suggested** match (same category, close before the refund date), and links on confirm. Linking is optional.
- **Tiles:** refunds this month, spent before refunds, spent after refunds. Summary and Trends use the after-refunds figure.
- **Refund month:** a refund lowers spending in the month it is logged, in its own category, even when the original was in an earlier month.
- As built (`src/pages/transactions`, helpers in `refunds.ts`):
  - A refund's original comes from the month's list, or `GET /v1/expenses/{id}` when it is in another month. "Refund for" links to `/transactions?month=<its month>#expense-<id>`; that row scrolls into view, takes focus and is outlined.
  - One tag per refund: "Not linked"; else "From <Month>" (with the year when it differs) when the original is in an earlier month; else "Full refund" when the refund covers the original's whole amount, otherwise "Partial refund".
  - Originals read `refunded_total_cents` and `last_refund_date` (both computed by the API, never stored). Net = amount + refunded total; at or below zero it is "Refunded in full" and the amount is struck through.
  - The refund chips (All, Refunds, Not linked) are their own group, kept in `?show=refunds|unlinked`, and combine with the category chips ("All categories") and the search.
  - The linking dialog lists expenses from the 90 days up to the refund's date (`GET /v1/expenses?from=&to=&type=expense`), searchable by merchant and note. **Suggested** is the closest expense on or before the refund in the same category whose net still covers the refund; it is preselected. Linking sends only `refunded_expense_id` (an unconfirmed refund stays unconfirmed) and confirms with a toast (`toast()` from `src/lib/toast.tsx`).
  - The tiles sit above Spending by category on every month: refunds (sum, count, how many linked), spent before refunds (expenses only) and spent after refunds.

## Interaction patterns

- Dialogs are real modal dialogs: focus trapped, Esc closes, `aria-modal`, labelled by their heading. Destructive ones use `role="alertdialog"` and a danger button that names the outcome (e.g. "Delete and move to Other").
- Toasts confirm background actions (backup finished, refund linked, user added). Feature code calls `toast(message)` from `src/lib/toast.tsx` (`toast.error` for failures, an optional `action` such as Undo) and never imports `sonner` itself; the one Sonner `<Toaster />` (`components/ui/sonner.tsx`, #173) is mounted in `AppShell`, bottom right. Its "Notifications" region is the polite live region; error toasts are `role="alert"`. Every toast has Dismiss and closes after 6 s, so a toast never holds the only copy of something the user needs: the screen shows it too. Tests that check a toast render `<Toaster />` beside the page.
- Filter chips and on/off toggles expose `aria-pressed` (`Toggle`). One-of-N choices, segmented toggles included, are `role="radiogroup"`/`role="radio"` (`ToggleGroup type="single"`, #170). **`Segmented`** (`src/components/Segmented.tsx`, #177) is the V2 segmented look on it (muted track, the chosen option on the card fill, 44px items); Summary's Bars / Donut, Trends' Amount / Count and Export's format (#178) use it.
- Charts get a text alternative (an `aria-label` per bar or a data table nearby).

## Quality

- Keyboard accessible, readable contrast in both themes, responsive down to laptop-sized windows. Layouts should still stack sensibly at phone width. The e2e suite checks every screen with axe (WCAG A/AA) in both themes, the focus ring, 44px targets, reflow and reduced motion (`e2e/tests/a11y.spec.ts`, #179).
- **Label in name (WCAG 2.5.3):** a control with an `aria-label` must contain its visible text, in the order shown. Rows built from several spans put a space between them (`{" "}`, which grid and flex rows don't draw), start with the visible label ("Jan: …", not "January: …") and leave out badges' own screen-reader words (`ChangeBadge decorative`). Row names: `charts/rowNames.ts`.
- **Reduced motion:** `src/index.css` (base layer) cuts every `[data-slot]` animation and transition to 0.01ms under `prefers-reduced-motion` (tw-animate-css doesn't check it). 0.01ms, not `none`, so Radix still gets `animationend`.
- **Touch targets:** 44px outside tables. `sm` and `icon-sm` (36px) and the batch entry's `cell` inputs are only for rows in a dense table.
- **Icons:** named `lucide-react` imports only (no `import *`, no `DynamicIcon`), so only the icons we use are bundled (41 of ~1,900 at #179).
