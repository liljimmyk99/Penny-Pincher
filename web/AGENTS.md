# AGENTS.md — /web

Read the root `AGENTS.md` first. This file adds rules specific to the React web app.

## Stack

- React (TypeScript recommended)
- **Build tool: Vite. Test runner: Vitest with Testing Library** (React Testing Library and `jest-dom` matchers). Component and screen tests run in Vitest's jsdom environment.
- Talks only to the backend API described in `/api`. Generate the API client/types from the OpenAPI spec rather than hand-writing them.
  - Types are generated by `openapi-typescript` into `src/api/schema.gen.ts` (never edit it). After changing the spec, run `npm run gen:api` and commit the result; `npm run check:api` fails if it is stale.
  - Calls go through the `openapi-fetch` client in `src/api` (`useApi()`), wrapped in `unwrap()` inside TanStack Query `queryFn`/`mutationFn`. Use `Schemas["Category"]` etc. for types.
  - The client adds the Firebase ID token as a bearer header, retries a 401 once with a refreshed token, and reports `unauthenticated` / `not_allowlisted` to one `onSessionError` handler (the app signs out there). `admin_required` is left to the caller.
  - Failures throw `ApiError` (`status`, `code`, `details`). Show `errorMessage(err)` to users and `fieldErrors(err)` next to form fields; branch on `code`, never on `message`.
- Auth uses the Firebase JS SDK (`firebase`, imports from `firebase/app` and `firebase/auth` only).
  - `src/auth/firebase.ts` is the only module that imports it (ESLint enforces this); everything else uses the `AuthService` interface. `main.tsx` imports the wrapper directly, so tests never load the SDK and use a fake (`src/test/fakeAuth.ts`).
  - The session store (`createSession`) is the API client's `onSessionError`: a 403 `not_allowlisted` signs out and the sign-in screen shows "No access" with the refused email.
  - The web config is public and baked in at build time: `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_PROJECT_ID`, optional `VITE_FIREBASE_AUTH_DOMAIN` (`web/.env.local` for `npm run dev`; Compose build args from the root `.env`).
- **Routing: React Router** (`react-router`). Routes live in `src/App.tsx` (`AppRoutes`) inside `AppShell` (`src/shell`); the sidebar order is `NAV_ITEMS` in `src/shell/navigation.ts`. Each screen renders a `Page` (`src/pages/Page.tsx`), which sets the tab title and gives the `h1` that takes focus after navigation. Tests render `AppRoutes` in a `MemoryRouter`.
- **No UI component library.** Build our own small components on the design tokens below. Radix UI primitives (unstyled) may be used for behavior that is hard to get right accessibly: dialogs, alert dialogs, popovers, menus, toggles and tooltips. All styling stays ours.
- **No charting library.** The approved charts (root §6.11) are hand-built React components, the same way the design canvas draws them:
  - ranked, paired, diverging and sparkline bars are elements sized as a percentage of the largest value (HTML or SVG)
  - the donut is a CSS `conic-gradient` ring (or SVG arcs)
  - one component per chart type (e.g. `RankedBars`, `PairedBars`, `DivergingBars`, `Donut`), shared by every screen
  - every chart has a text alternative (see Interaction patterns)
- Do not add a major dependency without noting it in the root file.

## Rules

- **Money** arrives as integer cents. Convert to display strings in one shared formatting utility; never do arithmetic on floats or on formatted strings.
- **Dates** are `YYYY-MM-DD` calendar dates. Do not let time zones shift them.
- **Online-only in v1:** no offline cache and no storing financial data in localStorage/sessionStorage. Show a clear error when a request fails. (UI preferences such as theme and sidebar state may be stored locally.)
- Keep server state in a data-fetching layer (e.g. TanStack Query or equivalent), not copied into component state.
- Auth is Firebase Authentication; keep the SDK behind a small wrapper module so the rest of the app never imports it directly.

## Design system

Define these as tokens (CSS custom properties or the UI library's theme) in one place. Do not scatter hex values through components.

**Type:** Manrope (400–800) from Google Fonts, system sans-serif fallback. Tabular numerals for every money column.
- Page title 32px/800 · section title 18px/800 · body 14px · tile value 26px/800
- Eyebrow labels: 12px/800, uppercase, 0.06em letter-spacing

**Shape and spacing:** cards radius 14px with a 1px border; buttons and inputs radius 10px, 44px tall; chips and pills fully rounded. Page padding 32px top, ~40px sides; 24px between sections, 16px between tiles. Touch targets at least 44px.

## Layout and navigation

- Left sidebar, 232px wide, dark background. Items in this order: Summary, Add entries, Transactions, Yearly, Trends, Templates, Categories & sources. The current page is highlighted (white pill) and marked `aria-current="page"`.
- **Collapsible sidebar:** a chevron button next to the logo collapses it to a ~76px icon-only rail (logo, icons, avatar) and the content widens. Links keep their accessible names when collapsed. Remember the choice per user (a UI preference, safe to store locally).
- Account button at the bottom of the sidebar opens a menu: name and email, Appearance (Light / Dark / System), Settings (⌘,), Export data, Admin dashboard (admins only), Sign out.
- Main content is fluid; cards and tables wrap or scroll horizontally inside their card on narrow windows. No horizontal page scroll.

## Screens

### Sign in and splash
- Split layout: brand panel left, sign-in card right.
- Continue with Google, plus email and password with a show/hide toggle.
- "Forgot password?" goes to a reset form, then a "check your email" confirmation (Firebase sends the email).
- Wrong credentials show an inline alert and mark the password field invalid.
- **No sign-up:** the card says accounts are created by an admin.
- While Firebase restores a session, show a full-screen splash ("Checking your session…").
- The Google button uses a neutral icon. If Google's official sign-in button is required, use their published asset, unmodified.

### Summary (landing, current month)
- Month switcher with previous/next.
- Four tiles: Net income, Spent, Saved & invested (counted in Spent), Left over.
- Income per source. Clicking a source opens a **modal** with that month's entries (gross, taxable, net, tax rate) and an "All sources combined" total.
- Spending by category as ranked bars, with a **Bars / Donut** toggle. Clicking a category row only **highlights** it.
- If template items are still unconfirmed, show an orange banner with a count.
- As built (`src/pages/summary`, charts in `src/charts`):
  - Reads `GET /v1/summaries/monthly/{month}` (`useMonthlySummary`); the month is `?month=` via `useMonthParam`. Percent of income (of combined net) and the change vs. last month are computed in the client (`summary.ts`, `lib/change.ts`).
  - Tiles: Net income, Spent (with change vs. last month), Saved & invested (counted in Spent; its change uses the Saving flip), Left over. They are muted for an empty month.
  - Income lists sources that have entries; a source opens `IncomeDialog` (that source's entries from `useMonthIncome`, its own total row and "All sources combined", with tax rates).
  - Spending is `RankedBars` (default) or the `Donut` with a legend, toggled by "Bars / Donut" (`aria-pressed`). Categories that net to zero or less get no bar. Rows are `aria-pressed` buttons that only highlight; their accessible name carries amount, percent of income and the change in words. Saving always uses `--color-saving-bar` and a "Saving" badge; other categories use their own colour, else `--chart-1…8`.
  - Change colours are the tokens `--color-worse` (orange) and `--color-better` (blue), always with ▲/▼ and a +/− sign.
  - Banner: the shared `UnconfirmedBanner` (with "Review in Transactions"). An empty month shows `NewMonthOffer` and dashed Income / Spending panels with "Add income" / "Add expenses".
  - Welcome card (`Welcome.tsx`): shown only on the current month while it is empty. Step 1 and "Hide" are remembered in localStorage (a per-viewer convenience); step 2 comes from the templates list, step 3 from the month having entries. It disappears once all three are done.

### Add entries
- Quick single entry plus a batch table ("Add row", remove row) for logging several at once. Keyboard-first.
- Fields: date, merchant (autocomplete from past merchants), category, amount, optional note.
- Income entries take source, gross, gross taxable and net.
- An "Add refund" action creates a refund and can link it to an original expense.
- As built (`src/pages/add`):
  - One table does both jobs: a single row is the quick entry, "Add row" makes it a batch. Every save goes through `POST /v1/expenses/batch` (all or nothing; item errors are shown on their rows). Blank rows are skipped.
  - **Enter** moves to the next row, adding one at the end; **⌘/Ctrl+Enter** saves all. New rows copy the previous row's date.
  - Merchant is an ARIA combobox over `GET /v1/merchants?q=`. Picking (or typing) a known merchant prefills the category from its latest expense, unless the user already chose one.
  - A refund row is one added with "Add refund", or any row with a negative amount; it is saved negative. "Refund for" lists that merchant's past expenses (`GET /v1/expenses?merchant_id=&type=expense`); picking one prefills its category. Linking stays optional.
  - The page month (`?month=YYYY-MM`, default current) sets the default date (today in the current month, else the 1st) and the income "so far" panel. Income's "Label" is the entry's note.

### Transactions (details)
- **Income table:** date, source, label, gross, taxable, net, tax rate, with a total row.
- **Spending by category:** clicking a category here **filters** the expense list (unlike Summary, which only highlights).
- **Expense list:** filter chips by category with counts, plus search over merchant and note.
- **Unconfirmed items:** light-orange row, a pill reading "Unconfirmed · from template", and a per-row Confirm button. A banner at the top has "Confirm all as-is".
- As built (`src/pages/transactions`):
  - The address holds the month (`?month=`, via `useMonthParam`, which Summary and Add entries share), the category filter (`?category=<id>`) and the search (`?q=`), so these views can be linked to.
  - Reads `GET /v1/expenses?month=` and `GET /v1/income-entries?month=` (all pages). Category totals, the income total row and its tax rate are summed in the client from those lists, so edits and deletes refresh them with the lists. Categories with no entries in the month are left out.
  - Edit opens a modal (`@radix-ui/react-dialog`) and sends only the changed fields (`PATCH`); a negative amount is a refund. Delete uses the shared `DeleteDialog`, which notes that a deleted expense's refunds stay, unlinked.
  - Unconfirmed rows get their colour, the unconfirmed pill and a per-row Confirm (`PATCH` with `confirmed: true` only). The banner and the template actions are as built under Empty states → New month. Refunds are as built under Refunds below.

### Refunds (in the transaction list)
- **Refund rows:** negative amount in refund green on a light-green row. Below the merchant: "Refund for <merchant · date · amount>", linking to the original.
- **Tags:** "Full refund", "Partial refund", "From <Month>" when the original is in an earlier month, or "Not linked".
- **Original expenses** show what happened to them: "Refunded in full on <date> · net $0.00", with the amount struck through, or "Partly refunded · −$X on <date> · net $Y".
- **Filter chips:** All, Refunds, Not linked.
- **Linking dialog:** for an unlinked refund, "Link…" opens a dialog that searches recent expenses, shows a **Suggested** match (same category, close before the refund date), and links on confirm. Linking is optional.
- **Tiles:** refunds this month, spent before refunds, spent after refunds. Summary and Trends use the after-refunds figure.
- **Refund month:** a refund lowers spending in the month it is logged, in its own category, even when the original was in an earlier month.
- As built (`src/pages/transactions`, helpers in `refunds.ts`):
  - A refund's original comes from the month's list, or `GET /v1/expenses/{id}` when it is in another month. "Refund for" links to `/transactions?month=<its month>#expense-<id>`; that row scrolls into view, takes focus and is outlined.
  - One tag per refund: "Not linked"; else "From <Month>" (with the year when it differs) when the original is in an earlier month; else "Full refund" when the refund covers the original's whole amount, otherwise "Partial refund".
  - Originals read `refunded_total_cents` and `last_refund_date` (both computed by the API, never stored). Net = amount + refunded total; at or below zero it is "Refunded in full" and the amount is struck through.
  - The refund chips (All, Refunds, Not linked) are their own group, kept in `?show=refunds|unlinked`, and combine with the category chips ("All categories") and the search.
  - The linking dialog lists expenses from the 90 days up to the refund's date (`GET /v1/expenses?from=&to=&type=expense`), searchable by merchant and note. **Suggested** is the closest expense on or before the refund in the same category whose net still covers the refund; it is preselected. Linking sends only `refunded_expense_id` (an unconfirmed refund stays unconfirmed) and confirms with a toast (`src/components/Toast.tsx`).
  - The tiles sit above Spending by category on every month: refunds (sum, count, how many linked), spent before refunds (expenses only) and spent after refunds.

### Templates
- Template list ("Your templates") and an editor for one template.
- Expense items take name, category, amount and day of month. Income items take source, label, gross, gross taxable and net.
- Apply a template to a chosen month. Copies land on each item's day of month; days that don't exist in that month (29–31) land on the month's last day (the backend does this, so don't recompute it in the client).
- As built (`src/pages/templates`):
  - Below 1400px wide, "Your templates" sits above the editor (as a row of buttons) so the item rows get the full width.
  - The chosen template is in the address (`?template=<id>`); without one, the first by name. "Your templates" shows each with its item count, plus "New template" (an inline name field; it is open from the start when there are none). Rename (dialog) and Delete (`DeleteDialog`, noting copied entries stay) sit beside the title.
  - Tiles: net income, planned spending (Saving included, with the saved amount noted) and left over, summed in the client from the template's items (`totals.ts`).
  - Income items first (source, label = the item's note, day, gross, gross taxable, net; with an "All sources" line and tax rate), then expense items grouped under every category in category order, empty ones included. Saving's group has its own tint and badge. Expense items take name (merchant, with autocomplete), an optional note, category (changing it moves the row), day and amount. The note tells apart several items from one merchant (e.g. two subscriptions from the same company); rows are labelled "<merchant> · <note>".
  - Rows edit in place. A saved row sends only its changed fields (`PATCH`) when focus leaves the row or on Enter. Any number of income and expense items can be added. "Add item" / "Add income" open a draft row that is created on Enter or Save (Enter then clears it for the next item, keeping category and day), or when focus leaves it complete. Remove deletes at once (items are cheap to re-add).
  - **Canvas differences:** the canvas's "Duplicate" button and "Default" badge have no backing in the spec or model, so they are not built. "Apply to <month>" lives with the template-copy flow (issue #30).

### Yearly
- Year switcher.
- Tiles: net income, spent, saved, left over for the year to date, with monthly averages.
- **Income vs. spent** paired bars per month. Clicking a month opens that month's Summary.
- Ranked category bars of monthly averages.
- Month-by-month table, where clicking a row opens that month; total and monthly-average rows at the bottom.
- As built (`src/pages/yearly`, `PairedBars` in `src/charts`):
  - Reads `GET /v1/summaries/yearly/{year}` (`useYearlySummary`); the year is `?year=` (default: current year). Tile averages and the table's average row are `total ÷ average_month_count` in integer cents, rounded half away from zero (`averageCents`).
  - Income vs. spent (net income and spent) is `PairedBars`: each month's pair is a button whose accessible name carries the figures and opens `/summary?month=`; the chart also has a visually hidden year summary. Category bars are `RankedBars` of `monthly_average_cents` (zero averages left out).
  - The table's month name is a link and the whole row is clickable; months without entries show "—".

### Trends
Two tabs at the top: **Custom trends** and **By category**.

- **Custom trends**
  - Saved trends list on the left. Each shows its name, what it matches, the measure and a mini bar sparkline.
  - Selected trend:
    - definition pills (match, category, tracking since)
    - an **Amount / Count** toggle
    - tiles: year-to-date total, monthly average with change vs. last month, peak month, average per visit
    - **vertical bars per month**: clicking a bar lists that month's matching entries, with "Open in Transactions"
  - **New trend dialog:** name, match by Merchant / Category / Note contains (merchant field offers frequent merchants), measure Amount / Count.
- **By category**
  - Category chips, including "All spending".
  - Tiles for the selected month: spend, change vs. previous month, change vs. same month last year, year-to-date vs. last year.
  - **Paired bars**: this year vs. last year per month. Clicking a month selects it.
  - **Biggest movers:** every category ranked by change vs. the same month last year, drawn as **diverging bars** around a centre line. Clicking a category charts it.
  - Month-by-month table: spend, change vs. prior month (January compares with last December), last year's spend, change vs. last year, and a year-to-date total.
  - Uses the change-indicator colours above, with Saving flipped.
  - As built (`src/pages/trends/CategoryTrends.tsx`, logic in `trendChange.ts`): reads `GET /v1/trends/by-category?year=` (`useCategoryTrends`) with its own year switcher; all comparisons are computed in the client. The month defaults to the current one (December for other years). Clicking a mover toggles that category (clicking it again returns to All spending). Months after today are dashed in the table. `PairedBars` gained `selectedId` and a `years` variant; `DivergingBars` is the new chart.

### Categories & sources
- **Expense categories**
  - Columns: drag handle to reorder (the order is used everywhere), name, entries, spent year to date.
  - Inline rename and delete.
  - Saving carries a "Counted as savings" badge.
  - **Other** carries a "Default" badge and a lock. It can never be renamed, edited or deleted, so it shows no actions and no drag handle.
- **Deleting a category:** a confirmation dialog states how many expenses (and how much) move to Other, and that templates using it switch to Other. Then Other's totals update.
- **Income sources:** entries, gross YTD, net YTD, calculated tax rate.
  - Inline rename for every source except "Other", which is locked like the Other category.
  - Delete is offered only for sources with no entries; its template items move to "Other". A source with entries shows no delete action (a tooltip explains it can be renamed but not deleted).
- An "Add category" / "Add source" field sits under each table.
- "Entries" counts all time; the money columns are year to date (root §10). The page eyebrow names the year.
- Reorder by dragging the handle, or from the keyboard with the arrow keys (Home/End) on it; "Other" keeps its place.
- **Canvas difference:** the canvas's income-source note and delete dialog say deleting a source moves its *income entries* to Other. That contradicts root §5 (a source with entries can never be deleted); this file wins, so the screen says a source with entries can only be renamed, and deleting an unused source moves its template items to Other.

  - Tiles show $0.00 in muted text.

  - A note says Yearly and Trends fill in as months are logged.

  - Summary offers **"Start <Month> from your template?"** with a preview of its bills and paychecks and their totals.
  - Actions: Copy into <Month>, Start blank, Edit template. Previous-month values are shown for reference.
  - After copying, an orange banner reads "N items copied … unconfirmed until you check each one", with Review in Transactions and Undo. Tiles and tables show the planned amounts with unconfirmed dots.

It offers the first template with items (a picker when there are several) and previews its paychecks and bills in day order, each beside last month's figure for the same merchant (or source and label), plus planned vs. last month's net, spending and left over. ## Interaction patterns

- Dialogs are real modal dialogs: focus trapped, Esc closes, `aria-modal`, labelled by their heading. Destructive ones use `role="alertdialog"` and a danger button that names the outcome (e.g. "Delete and move to Other").
- Toasts confirm background actions (invite sent, backup finished, refund linked). Use `role="status"` and make them dismissible.
- Segmented toggles and chips expose `aria-pressed`. Radio-style pickers use `role="radiogroup"`/`role="radio"`.
- Charts get a text alternative (an `aria-label` per bar or a data table nearby).
